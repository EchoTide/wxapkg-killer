# 微信小程序解包与暴露面审计

用 `wxapkg_*` 系列工具完成「定位 → 解包 → 检视 → 审计 → 出加固建议」。
不联网上传任何数据。解包和 `save_report` 会在本机写文件；检视类工具按调用方给出的路径读取，不是沙箱。

## 前置认知

`.wxapkg` 的加密密钥就是 **wxid 本身**，salt / IV / 迭代次数全是硬编码常量。
因此**只要包落在用户磁盘上，解密就是零成本的确定性操作**——不存在"解不开"的情况。
真正的问题是：**解开之后能看到什么**。

## 标准链路

```
wxapkg_scan → wxapkg_unpack → wxapkg_audit →（按需）wxapkg_search / read_file / list_files
```

1. **`wxapkg_scan`** — 列出本机所有缓存包：wxid、大小、修改时间、路径，按修改时间倒序。
   - 不传 `path`，自动探测微信 3.x / 4.x 默认目录。
   - **定位目标技巧**：让用户在 PC 微信里打开一次目标小程序，它就会排到列表最前。
2. **`wxapkg_unpack`** — 传 wxid 即可（密钥自动用 wxid）。默认开启解密与美化。
3. **`wxapkg_audit`** — 一次性产出结构化风险报告，这是主交付物。
4. 需要补充证据时再用 `search` / `read_file` / `list_files` 下钻。

**不要跳过 audit 直接手工 grep**——它已经做了白名单去噪、分包完整性比对和混淆度评估。

## 解读审计结果

| 章节 | 怎么看 |
| --- | --- |
| 技术栈识别 | 决定后续加固手段（Cocos / Laya / Taro 等各自有对应工具） |
| 后端接口域名 | **业务域名**才是风险项；公共域名已自动归入忽略区 |
| 敏感信息扫描 | 高危项优先看硬编码密钥、私钥、调试开关 |
| 微信 API 使用面 | 用了 `wx.request` 的域名、开放能力，可推断业务边界 |
| 分包完整性 | 缺失分包不影响结论，但会影响还原完整度 |
| 代码混淆程度 | **未混淆 = 业务逻辑接近源码可读**，是最强的加固信号 |

## 常见异常

- **扫不到包**：微信只在**实际打开过**之后才缓存。让用户先在 PC 微信里打开，再重扫。
- **分包缺失**：同上，微信按入口粒度缓存。需要用户在微信里点一遍对应入口再重新解包。
- **解包报"目录穿越"**：路径分隔符问题，通常已修复；若复现请检查输出目录是否含非 ASCII 字符。

## 给开发者的加固建议（按性价比排序）

1. **P0 — 核心逻辑下沉服务端**：战斗结算、抽卡概率、虚拟货币增减、排行榜，
   前端只上报原始输入，由服务端裁决。这是唯一能真正防住改包/改内存/伪造请求的措施。
2. **P1 — 代码混淆**：微信官方《游戏深度保护》插件（开发者工具 → 工具 → 插件 → 编辑器扩展，
   搜 `codeFortify`），带混淆、水印、代码锁、WASM 加固。
3. **P1 — 清理硬编码**：移除包内密钥；API 域名与 secret 改为运行时动态下发。
4. **P2 — 数据面收口**：数值配置加密，资源走 CDN 签名 URL + 有效期。
5. **P2 — 提审前剔除**：Mock 代码、调试开关、GM 指令、测试分支。

## 边界与合规

- 解包得到的是**编译态代码**：变量名可能被压缩，但字符串常量、接口地址、配置数值是明文。
- 本工具**不还原 WXML/WXSS**（上游只做解密与拆包）。
- 仅用于对自己拥有或已授权的小程序做安全自查。未经授权逆向他人小程序可能违反平台规则与法律。
